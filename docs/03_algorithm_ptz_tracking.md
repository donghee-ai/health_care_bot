# PTZ 추적 알고리즘 · 손실 복구

본 문서는 카메라가 사람을 따라가는 제어 법칙과 사람을 놓쳤을 때의 복구 동작을 수식
수준으로 정리합니다. 튜닝값을 만지기 전에 각 값이 무엇을 결정하는지 알도록 작성합니다.

구현: [`src/ptz_controller.py`](../src/ptz_controller.py) ·
[`src/pose_utils.py`](../src/pose_utils.py)
운동 카운팅은 [`04_algorithm_exercise.md`](04_algorithm_exercise.md).

## 0. 한 눈에 — 5단계 흐름

```
[1] MoveNet 17 keypoint (원본 픽셀 y, x, conf)
         ↓
[2] 추적 목표점 산출        종목별 (무릎 | 어깨) → 엉덩이 → 몸통 폴백
         ↓                  없으면 → [5] 손실 복구
[3] EMA 스무딩 (alpha 0.4)
         ↓
[4] 존 판정 + 제어          yaw: 중앙 4/6 섹터 밴드 / pitch: 데드존
     deg_per_s = clamp(gain * 오차) * scale
     목표각 += 부호 * deg_per_s * dt        → 소프트리밋 클램프 → 서보 전송
         ↓
[5] 손실 복구 (yaw 전용)    관성 → 대기 → 복귀 → 중앙. 재검출 시 즉시 취소
```

## 1. 컨벤션 — 두 좌표계를 섞지 말 것

| 대상 | 단위 | 범위 | 비고 |
|---|---|---|---|
| keypoint 배열 | 픽셀 `(y, x, conf)` | 원본 프레임 | **y가 먼저다** |
| 추적 목표점 `(tx, ty)` | 정규화 | 0~1 | 헬퍼가 `(x, y)`로 **뒤집어** 반환 |
| 서보각 `pan_deg`/`tilt_deg` | 도(°) | yaw 90~270, pitch 150~210 | **중앙 = 180°** (tick 2047) |
| 제어 출력 | deg/**s** | ±116 | 프레임당이 아니다 (§5) |

`pan_deg`/`tilt_deg`는 **우리가 명령한 목표각**이다. 서보의 실제 위치는 런타임에 읽지
않는다(버스 왕복 절약).

## 2. 추적 목표점 — 종목별 + 폴백 사슬

매 프레임 `main.py`가 `ptz.set_track_mode(exercise)`를 호출해 모드를 넘긴다
(`overhead`/`lateral` → `upper`, 그 외 → `lower`).

```
lower (스쿼트)   : 두 무릎 중점  → 엉덩이 중점 → 몸통 중심
upper (상체 2종) : 두 어깨 중점  → 엉덩이 중점 → 몸통 중심
```

- **무릎은 양쪽이 다 보일 때만 쓴다**(`require_both=True`). 한쪽만 보이면 그 다리로
  카메라가 쏠리기 때문에 엉덩이 중점(몸통 중심선)으로 폴백한다.
- 어깨를 쓰는 이유는 **머리 위로 든 팔이 잘리지 않게** 하려는 것이다. 무릎을 계속
  추적하면 상체 운동에서 팔이 프레임 밖으로 나간다.
- 세 단계가 모두 실패하면 `(None, None)` → 미검출 처리(§9).

> `stats.json`의 `person_center_norm`은 이것과 **다른 값**이다(표시용 중심점).
> 실제 추적점은 `ptz.target_norm`이다.

## 3. 스무딩

```python
smooth = alpha * new + (1 - alpha) * smooth      # alpha = smooth_alpha = 0.4
```

keypoint 지터가 그대로 서보 명령이 되는 것을 막는 1차 EMA. 첫 프레임은 관측값으로
초기화한다.

## 4. 존 판정 — yaw는 섹터, pitch는 데드존

```python
ex = smooth_x - 0.5        # 좌우 오차 (화면 중앙 기준)
ey = smooth_y - pt_y       # 상하 오차 (기준선은 모드별)

yaw_dead = 0.5 - sector_side          # = 1/3   (중앙 4/6 밴드의 반폭)
yaw_out   = abs(ex) > yaw_dead  or  (not knees_in_band)
pitch_out = abs(ey) > pdz
```

| 모드 | `pt_y` | `pdz` | 왜 |
|---|---|---|---|
| lower (스쿼트) | 0.62 | **0.20 (넓게)** | 무릎을 화면 하단쯤에. 넓은 데드존으로 **스쿼트 상하 바운스를 무시** |
| upper (상체) | 0.64 | 0.15 (좁게) | 어깨를 더 아래에 둬 머리 위 팔 공간 확보. 어깨는 상하로 안 흔들려 좁아도 됨 |

**yaw는 화면을 좌 1/6 · 중앙 4/6 · 우 1/6로 나눈 섹터 판정이다.** 목표점이 중앙 밴드
안이면 팬하지 않는다. 하체 모드에서는 조건이 하나 더 붙는다 — **양 무릎이 다 보이면 두
무릎의 x가 모두 밴드 안에 있어야** `knees_in_band`가 참이다. 중점은 중앙인데 다리가
벌어져 한쪽 무릎이 화면 가장자리에 걸린 상황을 잡아낸다.

> pitch가 `0.5 / 0.10`이던 시절엔 (1) 무릎이 원래 화면 아래쪽(0.79)이라 잠금이 영영 안
> 걸리고 (2) 스쿼트마다 카메라가 끄덕였다. `0.62 / 0.20`으로 둘 다 해결했다.

## 5. 제어 법칙 — 프레임당이 아니라 **초당**

```python
dt_s = clamp((now_ms - last_update_ms) / 1000, 0, max_dt_s=0.15)   # 첫 프레임은 0

deg_per_s = clamp(gain_deg_per_s * e, ±max_deg_per_s) * scale
pan_deg  += yaw_sign   * deg_per_s * dt_s          # 그리고 소프트리밋 클램프
tilt_deg += pitch_sign * deg_per_s * dt_s
```

| 파라미터 | 값 | 의미 |
|---|---|---|
| `gain_deg_per_s` | 232.0 | 정규화 오차 1.0당 각속도 (옛 `gain=8.0` × 29) |
| `max_deg_per_s` | 116.0 | 각속도 상한 (옛 `max_step=4.0` × 29) |
| `track_scale` | 0.5 | 추적 속도 1/2 |
| `both_knee_scale` | 0.5 | 양 무릎 보이면 추가 1/2 → **실효 상한 29 deg/s** |
| `max_dt_s` | 0.15 | LOST 구간을 건너뛴 직후 한 번에 튀는 것 방지 |

### 5-1. 왜 바꿨나 — 프레임레이트 의존성 제거

원래는 `step`을 **매 프레임 누적**했다. `gain=8.0`은 암묵적으로 개발 PC(~29 FPS)에 맞춰진
"프레임당 도수"였고, 11 FPS인 UNO Q에서는 같은 시간에 누적되는 프레임이 1/2.6이라
**각속도도 1/2.6**로 떨어졌다. 실기에서의 "톡톡" 끊김이 그 결과였다. deg/s로 정리하면서
제어식에서 프레임레이트 개념이 완전히 사라졌다.

검증 (합성 keypoint, 1초간 yaw 회전량):

| FPS | 이전 | 이후 | 29 FPS 대비 편차 |
|---|---|---|---|
| 29 (PC) | 25.20 | 25.20 | 0% — 회귀 없음 |
| 20 | 17.10 | 24.79 | 32% → 1.6% |
| **11 (UNO Q)** | **9.00** | **23.73** | **64% → 5.8%** |
| 6 | 4.50 | 19.57 | 82% → 22.3% |

6 FPS의 잔여 편차는 `max_dt_s` 상한이 걸린 것으로 의도된 동작이다.

## 6. 잠금 — "도리도리" 제거

```
존 안에 lock_frames(10) 연속 머무름  →  locked = True (명령 정지)

해제(히스테리시스):
  yaw   : abs(ex) > yaw_dead + yaw_reengage_hyst(0.05)  또는  무릎이 밴드 밖
  pitch : abs(ey) > reengage(0.18)                       ← pitch_deadzone(0.20)보다 작다
```

임계를 하나만 두면 경계에서 미세 진동할 때 카메라가 좌우로 떨린다. 잠금 상태에서는
**충분히 벗어날 때만** 추적을 재개한다. 잠금 중에는 `_last_yaw_vel = 0`으로 두는데, 이게
§9-1의 안전 성질과 직결된다 — 정지 중이었으니 관성의 근거가 없다.

## 7. 명령 쿨다운 — 250 ms → 80 ms

서보는 569 tick/s ÷ 11.375 tick/deg = **50 deg/s**로 도는데, 목표각이 밀리는 속도는 최대
29 deg/s다. **서보가 목표보다 1.7배 빠르니 매번 먼저 도착해서 남는 시간을 멈춰 있었다** —
250 ms 주기 기준으로 오차가 클 때도 주기의 42%, 절반일 땐 71%를 정지 상태로 보냈다.
이게 "톡톡"의 두 번째 원인이었다.

80 ms면 11 FPS(프레임 간격 91 ms)에서 사실상 매 프레임 전송이다. 1 Mbaud에 명령 15바이트라
버스 부하는 무시 가능하다.

## 8. 소프트리밋

**자동 추적 · 수동 조작 · 복구 동작 모든 경로**가 클램프를 통과한다.

```
yaw   : 90 ~ 270   (중앙 180 ±90)
pitch : 150 ~ 210  (중앙 180 ±30)
```

한계에서 밀어붙이는 시나리오로 검증됨 — 정확히 270.00 / 90.00에서 멈추고, 관성 속도도
`max_deg_per_s`에서 잘린다. 기구부를 바꿨으면
[`06_hardware_calibration.md`](06_hardware_calibration.md)로 재실측 후 이 값을 갱신해야 한다.

## 9. 손실 복구 사다리 (yaw 전용)

미검출 프레임에서만 진행한다. **어느 단계든 재검출되면 즉시 전부 취소**되고
(`_reset_recovery()`) 정상 추적으로 돌아간다. pitch는 건드리지 않는다.

```
연속 미검출 < 3프레임              → 아무것도 안 함 (단발 깜빡임 무시, 0.27초)
  ↓
coast    : 관성 15프레임 (11 FPS에서 ~1.36초), 프레임당 0.9 감쇠   [로그 COAST]
  ↓
hold     : 관성 끝 지점에서 1.0초 대기
  ↓
returned : 관성 이전 위치로 복귀 후 2.0초 대기                      [로그 BACK]
  ↓
centered : 중앙(180)으로 복귀하고 정지 — 사람 찾을 때까지 대기      [로그 CENTER]
```

`frame_out_grace(15)`는 이 사다리와 별개로 **상태 표시**(`state = lost`)에만 쓰인다.
복구는 3프레임부터 시작한다.

### 9-1. 관성 속도 — 두 성분의 합

```python
coast_vel = clamp(last_yaw_vel + yaw_sign * last_subject_vel * coast_fov_deg,
                  ±max_deg_per_s)

coast_left = coast_frames if abs(coast_vel) > 1.0 else 0    # 0이면 coast를 건너뛰고 hold로
```

- `last_yaw_vel` — **카메라가 이미 돌던 각속도** (deg/s)
- `last_subject_vel` — **화면 안에서 사람이 움직인 속도** (정규화 x/초).
  `(smooth_x - prev_smooth_x) / dt_s`로 낸다. 손실 구간을 건너뛴 델타는 시간 간격이
  불확실해 **버린다**(`had_misses`면 `prev`를 리셋).
- `coast_fov_deg`(60) — 정규화 이동량을 각도로 바꾸는 계수 = 카메라 수평 화각.

**왜 두 성분을 더하나** — 처음엔 카메라 각속도만 썼다가 실기에서 "빠르게 나가면 관성이
아예 안 걸린다"는 문제가 나왔다. 원인은 데드존이었다: 중앙 4/6 밴드 안에서는 카메라가 안
움직이므로 각속도가 0이고, 11 FPS면 2~3프레임에 중앙에서 화면 밖까지 갈 수 있다. 반대로
카메라가 잘 따라가던 중이면 화면 속 사람은 거의 정지해 보여 두 번째 성분이 0이다.
**한쪽만 보면 반드시 놓친다.**

| 시나리오 | 카메라 | 화면 내 | 관성 초기속도 |
|---|---|---|---|
| 느린 이탈 (밴드 밖 체류) | +22.48 | +0.53/s | +43.47 deg/s |
| **빠른 이탈 (중앙에서 사라짐)** | 0 | +1.02/s | **+49.00** |
| 초고속 (1프레임) | 0 | +1.32/s | **+63.36** |
| **중앙에서 정지 중 손실** | 0 | 0 | **0 → 관성 안 걸림** |
| 가장자리 정지 중 손실 | +23.19 | 0 | +18.62 |

**마지막 두 줄이 핵심 안전 성질이다.** 사람이 제자리에 있는데 검출만 깜빡인 경우 두
성분이 모두 0이라 관성이 아예 안 걸린다 — 헛발질이 이 규칙 하나로 걸러진다.

### 9-2. 감쇠가 거리를 지배한다

```python
pan_deg += coast_vel * dt_s
coast_vel *= coast_decay        # 프레임당
```

| `coast_frames` | 이동거리 | | `coast_decay` | 이동거리 |
|---|---|---|---|---|
| 10 | 24.85° | | 0.80 | 26.86° |
| 15 | 26.86° (+8%) | | 0.85 | 33.88° (+26%) |
| 30 | 27.81° (+12%) | | **0.90** | **44.22° (+65%)** |

**관성 거리를 바꾸려면 `coast_decay`를 만져야 한다.** `coast_frames`는 "얼마나 오래 꼬리를
끄는가"만 결정한다 — 뒤쪽 프레임의 속도가 이미 0에 가까워서다.

> **실기 확인 완료(2026-07-19)** — 현재 튜닝(15 / 0.9 / fov 60)으로 잘 따라간다. 최초
> 보고였던 "빠르게 나가면 못 따라온다"도 해소 확인됨.

### 9-3. 검토했으나 기각한 대안

- **관성을 등속(`decay=1.0`)으로** — overshoot 증가, FPS 의존 증가, 급정거.
  감쇠 유지가 맞다는 결론.
- 3프레임 필터를 늘리거나 "중앙에서 사라졌다"를 따로 판정 — 원인이 데드존이었으므로 둘 다
  증상만 건드린다.

## 10. 수동 조작 경로

```
POST /api/ptz {command: pan|tilt, delta_deg}
  → delta를 ±10°로 클램프
  → set_auto_track(False)          ← 자동 추적을 끈다
  → 목표각 갱신 + 소프트리밋 + 즉시 전송 (쿨다운 무시)
  → locked = False, _centered = 0  ← 잠금 해제
```

수동 조작이 들어오면 자동 추적을 끄는 이유는, 조작하는 동안 카메라가 계속 되돌아가면
조작 자체가 불가능해지기 때문이다. `center`는 auto 상태를 바꾸지 않는다. 자동 추적이 꺼진
상태에서도 `update()`는 계속 돌며 **상태만 갱신**한다(웹 UI 표시용).

## 11. 튜닝 요약

| 값 | 기본 | 언제 만지나 |
|---|---|---|
| `sector_side` | 1/6 | 좌우 추적을 더 민감하게(↑) / 둔감하게(↓) |
| `pitch_target_y` / `_upper` | 0.62 / 0.64 | **상체 운동에서 팔이 잘리면 `_upper`를 0.68~0.72로** |
| `pitch_deadzone` / `_upper` | 0.20 / 0.15 | 스쿼트 중 카메라가 끄덕이면 ↑ |
| `lock_frames` | 10 | 잠금이 너무 빨리/늦게 걸리면 |
| `reengage` | 0.18 | 잠금 해제가 너무 예민하면 ↑ |
| `track_scale` | 0.5 | 전체 추적 속도 |
| `coast_decay` | 0.9 | **관성 이동 거리** (0.8→27°, 0.9→44°) |
| `coast_fov_deg` | 60 | 관성 속도. **추정값 — 실측 보정 가능** |
| `command_cooldown_ms` | 80 | 프레임 간격보다 짧게 유지 |

전부 `main.py` CLI 플래그로도 조절된다(`--sector-side`, `--pitch-target-y`,
`--lock-frames`, `--track-scale`, `--both-knee-scale`, `--yaw-sign`, `--pitch-sign` 등).

`coast_fov_deg` 보정법: 카메라를 알려진 각도만큼 돌려놓고 피사체가 화면 폭의 몇 %만큼
밀리는지 재면 나온다 (15° 회전에 30% 밀리면 화각 = 15 / 0.30 = 50°).

## 12. 알려진 한계

- **`coast_frames`만 아직 프레임 수 기준이다.** 추적 제어는 시간(deg/s)으로 바꿨는데 관성
  지속만 프레임이라, FPS가 다르면 지속 시간과 거리가 달라진다(11 FPS에서 1.36초 = 1.00 /
  29 FPS에서 0.52초 = 0.38). **PC에서 디버깅하면 관성이 2.6배 짧게 보인다** — PC와 실기를
  비교할 때 혼동 주의. 고치려면 `coast_duration_s`로 바꾸고 감쇠도 `decay^(dt/기준dt)`로
  환산해야 한다.
- `coast_fov_deg=60`은 실측이 아닌 추정값이다(실기에서 충분히 동작해 보류 중).
- 서보 실제 위치를 읽지 않으므로 목표각과 실제각이 어긋나도 감지하지 못한다.
- pitch에는 손실 복구가 없다(yaw 전용).
