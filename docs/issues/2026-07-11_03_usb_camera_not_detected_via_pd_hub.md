# PD 허브 경유 시 USB 카메라(+모든 USB 장치)가 전혀 열거되지 않음 (PC 재연결로 해결)

## 증상

UNO Q(`unoq-korea01`)의 USB-C 포트(보드에 있는 유일한 USB 포트, USB-A 등
별도 호스트 포트 없음)에 PD 허브를 연결 — 허브가 보드 전원(PD)과 카메라를
동시에 공급하는 구조. `docker run`으로 `main.py` 실행 시
`ERROR: cannot open camera /dev/video0` (`/dev/video0`·`/dev/video1`은
Qualcomm Venus 코덱 노드, 실제 UVC 카메라 아님). `lsusb`에 root hub 2개만
보이고 외부 허브·카메라가 전혀 안 잡힘. 카메라 대신 단순 USB 저장장치를
같은 허브에 꽂아도 마찬가지로 전혀 인식 안 됨 — 카메라 특정 문제가 아님.

## 원인

**허브가 PD로 전원을 내보내는 것과 USB 데이터 허브 역할을 동시에 수행하지
못함.** 같은 허브를 일반 PC에 "PD 없이"(PC가 자체 전원으로 동작, 허브는
순수 데이터 허브 역할만) 연결하면 데이터 인식이 정상 동작하는 것을 확인 —
즉 허브의 데이터 라인 자체는 멀쩡하다. 문제는 UNO Q처럼 **허브가 다운스트림
호스트(보드)에 PD로 전원을 공급해야 하는 상황에서만** 재현됨. 허브
칩셋/펌웨어가 "PD power delivery 협상 활성" 상태에서 USB data mux를
제대로 유지하지 못하는(또는 아예 꺼버리는) 것으로 보인다.

이 결과로 "PD 전원 공급 + 데이터 허브"를 표방하는 제품이라면 **핵심 광고
기능(동시 지원)이 실제로 안 되는 것**이 확인된 셈 — 환불/교환 사유로
타당함.

### 확인 과정에서 배제한 가설들 (기록용)

- ~~허브/케이블에 데이터 라인이 아예 없음(충전 전용)~~ — PC에 PD 없이
  연결했을 때 데이터가 정상 동작하는 것으로 기각. 데이터 라인 자체는 있음.
- ~~보드가 host VBUS를 안 내보내는 문제~~ — `power_role: [sink]` 확인 후
  기각. Sink 역할이면 VBUS는 허브가 공급하는 게 정상.
- ~~보드가 Sink(전원)+Host(데이터) 동시 지원 안 됨~~ — `/sys/class/typec/port0/data_role`이
  이미 `[host] device`로 잡혀 있어 role 조합 자체는 문제 없음. 보드 쪽은
  정상.
- `dmesg`의 `l5: disabling` / `usb_vbus: disabling` (boot ~34s) — WiFi 연결
  직후 타이밍인 걸 보면 카메라/허브와 무관하게 부팅 후 아무도 안 쓰는
  레귤레이터를 커널이 정리하는 정상 동작으로 재해석. red herring이었음.

## 해결

**허브를 PC에 한 번 연결했다 뺀 뒤 다시 UNO Q에 꽂으면 초기화되어 카메라가
정상 인식됨.** 하드웨어 교체 없이 이 재연결 트릭으로 해결.

- 허브 교체는 필요 없어짐 — 데이터 라인 자체는 처음부터 멀쩡했고
  (위 "확인 과정에서 배제한 가설들" 참고), PD 활성 상태에서 걸리던
  negotiation이 PC 재연결로 리셋되는 것으로 보임.
- **다만 재발 가능성 있음** — 근본적으로 왜 이 상태에 빠지는지(펌웨어
  버그 vs 특정 negotiation 타이밍)까지는 확인 못 함. USB 재연결/재부팅마다
  카메라가 다시 안 잡히면 같은 방법(허브를 PC에 잠깐 연결 후 재초기화 →
  UNO Q에 재연결)으로 대응.
- `docs/history/2026-07-11_05_pd_hub_confirmed_defective_refund.md`에
  최종 결과 기록.

## 재발 방지

- "PD 전원 + USB 데이터"를 한 허브로 동시에 쓰는 구성을 짤 땐, 구매 전에
  "simultaneous power delivery and data" 또는 이에 준하는 문구가 제품
  스펙에 명시돼 있는지 확인할 것.
- 카메라가 다시 안 잡히면 우선 **허브를 PC에 재연결해 초기화**해보고,
  그래도 안 되면 아래 순서로 SSH만으로 좁힐 수 있음: (1) `lsusb`/`dmesg | grep usb`
  로 완전 무반응인지 확인 → (2) `/sys/class/typec/port0/{power_role,data_role}`
  로 role 협상 자체는 됐는지 확인(보드 쪽 문제 배제) → (3) 카메라 대신
  단순 USB 저장장치로 교차검증(카메라 특정 문제 배제) → (4) 같은 허브를
  PD 없이 일반 PC에 연결해 데이터 라인 자체 결함인지 구분.
