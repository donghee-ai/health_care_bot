# 한글 웹폰트를 코드포인트 순으로 쪼개면 아무 효과가 없다

## 증상

Pretendard 2.0MB를 줄이려고 `unicode-range`로 44조각(조각당 256음절)을
만들었다. 브라우저는 "실제로 그리는 글자가 든 조각만" 받아가므로 크게
줄 것이라 기대했다.

실측해보니 **텍스트가 많은 화면이 37조각을 요청**했다. 거의 전부를
받은 셈이라 쪼갠 의미가 없었다.

```
almanac  woff2 요청: base kr-00 kr-01 kr-02 kr-04 kr-05 kr-06 kr-07 kr-08
                     kr-09 kr-11 kr-12 kr-13 kr-14 kr-15 kr-16 kr-17 kr-20
                     kr-21 kr-22 kr-25 kr-26 kr-27 kr-28 kr-29 kr-32 kr-33
                     kr-34 kr-35 kr-36 kr-38 kr-39 kr-40 kr-41 kr-42 ...
```

## 원인

한글 음절 11,172자를 코드포인트(`U+AC00`~`U+D7A3`) **순서대로** 자르면,
조각 하나에 "가·각·갂·갃…" 같이 **초성이 같은 글자들만** 들어간다.

그런데 실제 문장은 초성이 골고루 흩어져 있다. "무릎과 발끝이 안정적입니다"
한 문장만 해도 ㅁ·ㄹ·ㄲ·ㅂ·ㄹ·ㄲ·ㅇ·ㅈ·ㅈ·ㅇ·ㄴ·ㄷ — 12자에 조각이
10개쯤 걸린다. 화면 하나만 그려도 대부분의 조각을 건드리게 된다.

즉 **코드포인트 순서와 사용 빈도 사이에 아무 상관이 없다.**

## 해결

빈도순으로 재배치한다. 소스에 실제로 등장하는 글자만 모아
**우선 조각(`kr-core.woff2`)을 만들고 맨 앞에 선언**한다.

```python
def used_hangul() -> set[int]:
    """src/ 안 문구에 실제로 등장하는 한글 음절."""
    out = set()
    for path in (ROOT / "src").rglob("*"):
        if path.suffix not in {".ts", ".tsx", ".css", ".html"}:
            continue
        for ch in path.read_text(encoding="utf-8"):
            if HANGUL_START <= ord(ch) <= HANGUL_END:
                out.add(ord(ch))
    return out
```

나머지 음절은 코드포인트 순 조각으로 뒤에 남긴다. 이때 **우선 조각에
든 글자는 뒤쪽 조각에서 빼야 한다** — 같은 코드포인트를 두 face가 함께
주장하면 어느 쪽이 이길지 브라우저 구현에 맡기게 된다.

## 결과

| | 이전 | 이후 |
|---|---|---|
| woff2 요청 수 | 37 | 3~4 |
| 폰트 전송량 | ~1.9 MB | 226~346 KB |

## 왜 "쓰는 글자만 남기기"로 안 갔나

가장 작아지지만, 한국어 문구를 한 글자라도 바꾸면 두부(□)가 뜬다.
서버가 보내는 문자열까지 생각하면 더 위험하다.

우선 조각 + 안전망 조각 구조는 **모든 글자가 어딘가에는 있으므로
두부가 원천적으로 불가능**하면서, 평소에는 우선 조각 하나로 끝난다.

## 재발 방지

한국어 문구를 크게 바꿨거나 폰트를 추가했으면 다시 돌린다:

```bash
cd web && python scripts/subset_pretendard.py
```

돌리지 않아도 안전망 조각이 받쳐주므로 화면이 깨지지는 않는다.
다만 요청 수가 늘어나므로 주기적으로 갱신하는 게 좋다.
