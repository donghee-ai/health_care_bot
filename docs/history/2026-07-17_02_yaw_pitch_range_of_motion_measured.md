# 2026-07-17 — yaw/pitch 실제 가동범위 측정 완료 (±90° / ±30°)

## 시점

2026-07-17 (중앙 캘리브레이션 완료 직후,
[`2026-07-17_01_yaw_pitch_center_calibration_completed.md`](2026-07-17_01_yaw_pitch_center_calibration_completed.md) 이어서)

## 사건

중앙 캘리브레이션(tick 2047) 완료 후, `scripts/test_st3215_serial.py`의
`move` 명령으로 실제 좌/우(yaw), 위/아래(pitch) 끝까지 돌려보며 전압/온도를
같이 확인하는 방식으로 **실제 가동범위를 실측**했다. 동시에 다른 터미널에서
바로 실행 가능한 긴급 정지 명령(`stop`, torque 즉시 OFF)을 준비해두고
진행했다.

## 배경

기존에 알고 있던 안전 범위는 사용자가 케이블 꼬임을 기준으로 추정한
값(yaw ±90°, pitch ±20°)뿐이었고, `health_care_ptz.ino`의 `PITCH_MIN/MAX`
(30/150, 중앙 90 기준 ±60)는 훨씬 이전 PWM 서보 시절 값이라 이번 ST3215
교체 후 실측 근거가 전혀 없었다. 짐벌 조립 후 진짜 안전 범위를 확정해야
`.ino`의 clamp 값을 신뢰할 수 있는 상태였다.

## 결과

- **yaw(ID=1)**: 중앙(180°) → 좌 90° → 중앙 → 우 90° → 중앙, 전 구간 목표
  대비 ±0.5° 이내로 정확히 도달. 전압 12.2~12.3V, 온도 41°C로 이동 내내
  일정 — 스톨/과부하 징후 없음. **±90° 전 구간 안전 확정** (기존 추정과
  일치).
- **pitch(ID=2)**: 방향(+/-가 위/아래 중 어느 쪽인지) 자체가 미검증 상태라
  -15°로 먼저 시도 → 사용자가 실제로 "위로 갔다"고 확인해줘서 **음수=위,
  양수=아래**로 방향 확정. 이후 위로 -30°, 아래로 +30°까지 실측 — 원래
  케이블 기준 추정치(±20°)보다 실제 여유가 더 있음을 확인, **최종 ±30°로
  상향 확정**.
- 코드 반영: `health_care_ptz.ino`의 `PITCH_MIN/MAX`를 `30/150`(근거 없는
  옛 값)에서 **`60/120`(중앙 90 기준 ±30, 실측값)**으로 수정.
  `YAW_MIN/MAX`(0/180, ±90)는 이미 실측과 일치해 변경 없음.
- 측정 후 두 서보 모두 중앙(180°)으로 복귀.

## 캘리브레이션 도구 정리 (같은 세션)

사용자 요청으로 `scripts/test_st3215_serial.py`(순수 벤치 테스트:
ping/read/move/sweep/set-id/dual-spin)와 캘리브레이션 로직을 분리:
- `scripts/st3215_bus.py` (신규) — 프로토콜 저수준 공용 모듈 (패킷 조립,
  레지스터 read/write, sign-magnitude 인코딩 등). 두 스크립트가 공유.
- `scripts/calibrate_st3215.py` (신규) — `calibrate`(ID 1,2 전체 재캘리브레이션,
  torque 안전 처리 자동), `set-center`(서보 하나만), `stop`(긴급정지) 전용.
