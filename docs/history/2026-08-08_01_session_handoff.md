## 1. 한 줄 요약

운동과 완전히 분리된 **경비(guard) 모드**를 새로 만들었다(홈 자세 대기 → 사람 감지 시
추적+자동촬영 → 10초 미검출 시 홈 복귀). 그 과정에서 PTZ 모드전환 잠금 버그·
`docker/run.sh` tty 버그·QR 정적이미지 함정을 고쳤고, **정전으로 인한 공유기 무선
클라이언트 격리 고착**이라는 오늘 하루 대부분을 잡아먹은 네트워크 문제를 풀었다.
마지막으로 **Tailscale + Funnel로 외부(다른 와이파이/데이터)에서도 접속 가능**하게
만들었다.

- 서비스: `screen -S hcb` 세션 안에서 `bash docker/run.sh` 실행 중.
- **로컬 LAN**: `http://192.168.0.50:8080/app`
- **외부(Tailscale Funnel, 필요할 때만 켤 것)**: `https://<기기이름>.<tailnet>.ts.net/app`
  - 켜기: `sudo tailscale funnel --bg 8080`
  - 끄기: `sudo tailscale funnel --https=443 off` (다 보여준 뒤 반드시 끌 것 — 이 앱은
    PIN(`1234`) 하나 말고 실질적 인증이 없어서, 링크 아는 사람 누구나 카메라/PTZ/경비

  - UNO Q의 Tailscale IP: `tailscale ip -4`로 확인 (자기 기기끼리는 Funnel 없이 이걸로도 접속 가능)
- PTZ pitch 부호: **`PITCH_SIGN=-1`이 새 기본값** (2026-08-06 짐벌 재조립 이후 확정,
  `docker/run.sh`/`main.py`/`ptz_controller.py` 전부 반영됨).

**실행/중지:**

## 3. 오늘 한 일 (주제별)

1. **경비(guard) 모드 신설** — 운동이 아닌 4번째 모드. 전환 즉시 홈(중앙) 정렬 → 5초
   무장 딜레이 → 사람 감지 시 원본 프레임을 `captures/`에 저장 + `guard_log.jsonl`에
   로그 → 10초 이상 미검출이면 자동으로 홈 복귀. PTZ는 무릎/어깨 우선순위 없는
   `person_center_normalized` 기반 전신 추적(`track_mode="guard"` 신설).
2. **PTZ 모드전환 시 잠금 안 풀리는 버그 수정** — 스쿼트에서 잠긴 채 상체운동으로
   바꿔도 안 움직이던 문제. `set_track_mode()`가 실제 전환 시 `locked`를 강제 리셋.
3. **`docker/run.sh` tty 버그 수정** — `-it` 고정이라 비대화형 SSH 등 tty 없는
   세션에서 `the input device is not a TTY`로 조용히 죽던 문제. tty 유무를 감지해
   없으면 `-it` 없이 뜨도록 수정.
4. **QR 정적이미지 함정 해결** — 모바일 접속 QR이 특정 시점 IP로 미리 렌더링한
   그림이라 IP 바뀌어도 절대 안 바뀌는 함정이었음. 외부 CDN 없이(로봇 Wi-Fi에
   인터넷 없을 수 있음) 브라우저 안에서 그 자리에서 QR을 인코딩하는 자체 생성기
   내장(`qrSvg()`, 버전1~4·ECC-M·마스크0 고정). jsqr로 실제 디코드 검증 완료.
5. **네트워크 대장정 (오늘 몇 시간 소모)** — 결론: **정전으로 집 공유기(5GHz 대역)가
   비정상 재부팅 → 무선 클라이언트 격리 상태로 고착**. PC는 사실 유선으로 나가고
   있어서 무선 격리를 안 타고 있었을 뿐이었고("PC는 되는데 폰만 안 됨"이 오히려
   격리의 증거였음), 문제의 AP를 한 번 더 깨끗하게 재시작하니 해결. 상세 진단
   순서는 [[project_hcb_demo_network]] 메모리에 기록.
6. **Tailscale + Funnel로 원격 접속 구축** — 다른 와이파이/모바일데이터에서도
   `https://<기기이름>.<tailnet>.ts.net/app`으로 접속 가능. 이 과정에서
   **프론트엔드가 API 주소를 `:8080`으로 하드코딩**하고 있어 Funnel(외부 포트가
   8080이 아님)에서 스트림/상태가 안 들어오던 버그도 같이 발견·수정
   (`location.origin`을 그대로 쓰도록 변경).
7. **모바일 UI 개선 3건**:
   - 링 안 숫자가 모바일에서 살짝 어긋나던 버그 — `<svg width="96" height="96">`
     하드코딩이 84px 컨테이너보다 커서 삐져나간 것. `width/height:100%`로 수정.
   - 무장 중 큰 숫자가 촬영 매수(예: "18")를 보여주면서 라벨은 "무장 중"이라
     안내문구("2초 뒤...")랑 안 맞던 버그 — 무장 전엔 숫자=남은 초로 통일.
   - "무장" 용어를 "N초 뒤 경비를 시작합니다"로 순화.
8. **경비 모드 PTZ 패널 모바일 레이아웃 재구성** — "최근 촬영" 상시 스트립이 화면을
   너무 잡아먹어 카메라 뷰가 눌리던 문제 → 버튼+시트(모달)로 전환. "직접 조작" 탭의
   조이스틱을 오른쪽으로 옮기고 왼쪽에 "🖼 사진 보기"/"● 직접 촬영" 버튼 추가.
9. **"직접 촬영" 버튼 쿨다운 공유 버그 수정** — 자동 감지랑 같은 5초 쿨다운을 써서,
   사람이 화면에 계속 있으면(테스트 중 본인) 자동 촬영이 쿨다운을 계속 선점해
   버튼을 눌러도 조용히 씹히던 문제. 수동 촬영은 쿨다운 무시하고 무조건 즉시
   촬영하도록 분리 + 버튼에 "촬영 중…/촬영됨!" 시각 피드백 추가.
10. **캡처 목록 API 신설** — `GET /api/guard/captures`(최근 N개), `GET /captures/<file>`
    (이미지 서빙), 웹에서 썸네일 그리드 + 탭하면 라이트박스로 크게 보기.

## 4. 코드 변경 (건드린 파일)

**백엔드 (`src/`):**
- `app_state.py` — guard 모드/무장타이머/촬영쿨다운/수동촬영 플래그 상태 전체.
- `guard_capture.py` (신규) — 사람 감지 판정(어깨+엉덩이 keypoint) + JPEG 저장 + 로그.
- `ptz_controller.py` — `track_mode="guard"` 추가(전신 추적 타깃), guard 진입 시 홈
  정렬, 10초 미검출 홈 복귀(`_guard_home`), 모드전환 시 `locked` 강제 리셋,
  `pitch_sign` 기본값 `-1`.
- `main.py` — guard 분기(스켈레톤 오버레이 생략, 자동/수동 촬영 트리거),
  `--pitch-sign` 기본값 `-1`.
- `http_server.py` — `/api/guard/capture-now`, `/api/guard/captures`,
  `/captures/<file>` 라우트 추가.
- `docker/run.sh` — `PITCH_SIGN`/`YAW_SIGN` 환경변수 지원(기본 -1/1), tty 감지 후
  `-it` 조건부 적용, `python3 -u`(무버퍼링, 로그 캡처용).

**프론트 (`web/dist/index.html`):**
- 설정(⚙️) 시트에 "운동 모드 / 경비 모드" 전환 세그먼트 신설 — 하단 운동
  세그먼트(스쿼트/숄더프레스/레터럴)와 완전히 분리.
- 모바일 접속(QR)을 별도 아이콘(⊞)/시트로 분리.
- 자체 QR 생성기(`qrSvg()`) 내장 — 정적 이미지였던 걸 런타임 인코딩으로 교체.
- `API` 상수를 `location.origin`으로 변경(포트 하드코딩 제거).
- 경비 모드 링/숫자 로직(`paintGuardRing`) — 무장 전/후 다른 숫자·라벨, "reps" 공유
  변수 동기화 버그 수정.
- 경비 모드 "직접 조작" 패널 — 조이스틱 우측 배치 + 좌측 "사진 보기"/"직접 촬영" 버튼.
- 촬영 갤러리 시트(`#capturesSheet`) + 라이트박스(클릭 시 확대).
- `.ring svg{width:100%;height:100%}` 정렬 버그 수정.

## 5. 다음 할 일 (미해결, 우선순위)

1. **스쿼트↔숄더프레스 전환 시 pitch 범위 문제** — 무릎-어깨 각도차가 ±30° 범위
   거의 끝까지 써서, 카메라-사람 거리가 가까우면 전환 중 사람을 놓칠 수 있음.
   사람이 카메라에서 더 멀리 서서 재테스트 필요(가설: 거리 늘리면 각도차 줄어듦).
2. **동시 뷰어 2명(PC+폰) 이상일 때 FPS 저하** (10→8 관측) — Python GIL 스레드
   경합 + Tailscale Funnel 암호화 오버헤드가 겹친 것으로 추정. `--jpeg-quality`를
   낮추는 게 쉬운 완화책이나 아직 미적용(run.sh에 옵션 미노출).
3. 캡처 파일이 계속 쌓이는데 자동 정리(오래된 것 삭제) 로직 없음 — 필요하면 추가.

## 6. 오늘 새로 안 함정 (재발 방지)

- **웹 프론트에서 API 주소를 특정 포트로 하드코딩하지 말 것** — `location.origin`을
  그대로 써야 리버스 프록시/터널(Funnel 등) 어떤 경로로 접속해도 깨지지 않는다.
- **정적으로 미리 렌더링해둔 QR/URL 이미지는 절대 만들지 말 것** — IP가 바뀌는
  프로젝트라 반드시 런타임에 다시 계산해서 그려야 한다.
- **"PC는 되는데 폰만 안 됨"이 무선 격리를 배제하는 근거가 아니다** — PC가 실제로
  같은 무선 경로를 타고 있는지 `Find-NetRoute`(Windows)로 먼저 확인할 것. 유선으로
  나가고 있으면 격리 테스트 자체가 무의미하다.
- **SSH 세션에 PC용 명령(`py -3.14`, PowerShell 문법)을 그대로 붙여넣기 쉬움** —
  디바이스 프롬프트(`arduino@unoq-korea01:~$`)인지 항상 먼저 확인.
- **PowerShell로 `tar | ssh` 파이프하면 바이너리가 깨짐** — Git Bash에서 하거나,
  파일로 먼저 tar 떠서 scp로 옮길 것.
- **자동 감지와 수동 트리거가 같은 쿨다운/락을 공유하면 안 됨** — 사용자가 명시적으로
  누른 버튼은 자동화 로직의 상태(쿨다운 등)와 무관하게 항상 즉시 반응해야 한다.
  안 그러면 "가끔 안 먹히는" 것처럼 보여서 디버깅하기 어렵다.
- **SVG에 `width`/`height` 속성을 하드코딩하면 CSS로 컨테이너 크기를 줄여도 그
  값 그대로 렌더링돼 삐져나온다** — 반응형이 필요하면 `width:100%;height:100%`로
  덮어써야 한다(viewBox는 내부 좌표계만 정의, 실제 렌더 크기는 별개).
