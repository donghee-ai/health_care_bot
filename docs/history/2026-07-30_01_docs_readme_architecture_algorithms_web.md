## 왜

히스토리(`docs/history/`)는 "언제 무엇이 있었나"를 남기는 데는 좋지만, **"지금 어떻게

같은 정보가 여러 히스토리에 조금씩 다른 버전으로 흩어져 있는 것을 확인했다
(예: PTZ 관성 튜닝값이 `2026-07-19_02` 요약 블록에는 stale하게 10/0.8로 적혀 있고
본문에는 15/0.9로 적혀 있다).

`exercise_detection.md`가 종목 설계에 대해 이 역할을 이미 하고 있었으므로, 같은 방식으로
**아키텍처·알고리즘·웹**에 상설 문서를 만들었다.

### 1. `README.md` 전면 최신화

낡아서 **틀린 내용**이었던 것:

- 기능표에 **푸시업**이 남아 있었다(07-26에 삭제됨). 숄더프레스·레터럴이 없었다.

- 폴더 구조에 `web/`, `docs/`, `design_demos/`, `backup/`, `stl/`이 아예 없었다.

새로 담은 것: 문서 지도, 실측 성능(11.4 FPS invoke 바운드 · CPU 83%), 디바이스/PC

### 3. `docs/algorithms.md` (신규)

PTZ 제어와 rep 카운팅의 수식·상태 전이·튜닝값.

- PTZ: 컨벤션 → 목표점 폴백 사슬 → EMA → 섹터/데드존 판정 → **deg/s 제어 법칙**
  (프레임당에서 초당으로 바꾼 이유 + FPS별 검증표) → 잠금 히스테리시스 → 쿨다운
  80ms 근거 → 소프트리밋
- **손실 복구 사다리** 전체: 3프레임 필터 → coast(15f/0.9) → hold 1s → BACK 2s → CENTER.
  관성 속도 = `카메라 각속도 + 화면 내 이동량 × 화각` 공식과 **두 성분이 모두 0일 때
  관성이 안 걸리는 안전 성질**, 감쇠가 거리를 지배한다는 측정표, 기각된 대안(등속 전환)
- 카운팅: `angle_3pt` 정의역 보호 + conf 게이트 → `RepCounter` 상태기계(히스테리시스 +
  dwell) → 종목별 임계·rep 정의 → **상체 2종이 각도 하나를 공유하는 이유**
- **알려진 실패 모드**를 숨기지 않고 적었다: `bottom=5°` 가짜 rep, 2D 투영 왜곡,
  rep 하나가 유효 샘플 2개로 성립하는 취약점, 기각한 대응 2건과 그 이유, 향후 후보
- 파일/함수 지도

## 작성 방식

**문서를 문서로부터 쓰지 않고 코드에서 확인해 썼다.** `src/*.py` 전부(2,027줄),

## 발견 — 코드에 남은 낡은 것 (문서에 기록, **미수정**)

1. **`docker/Dockerfile`의 `CMD`가 `--mode auto --serial /dev/ttyUSB0`** — `auto`는
   07-26에 argparse에서 제거됐다. 실사용 경로(`run.sh`)가 명령을 덮어쓰므로 지금은
   증상이 안 보이지만, **손으로 `docker run`하면 `invalid choice: 'auto'`로 즉시 종료된다.**
   07-26에 `run.sh`에서 고친 것과 **정확히 같은 함정이 Dockerfile에 하나 더 남아 있었다.**
2. **`st3215_bus.py::set_id` docstring**이 "실제 반영은 전원 재투입 후"라고 적고 있는데,
   실기에서는 즉시 반영되는 것으로 확인됐다(`issues/2026-07-16_01`). 코드 주석이
   이슈 문서와 반대다.
3. `pose_utils.py`·`exercise_counter.py`·`Dockerfile` 주석에 "squat + pushup"이라는 옛
   표현이 남아 있다(동작 무해).
