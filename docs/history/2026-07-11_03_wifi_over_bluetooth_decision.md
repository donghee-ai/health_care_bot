# 2026-07-11 — 네트워크 의존성 완화안으로 Bluetooth 검토 후 기각

## 시점

2026-07-11

## 사건

사용자가 "같은 네트워크에 있어야 한다"를 웹앱의 최대 단점으로 지목하며
Bluetooth 기반 앱 전환 가능성을 문의. 검토 후 WiFi/HTTP 아키텍처 유지로
결론.

## 배경

Health Care Bot Live는 로컬 LAN 전용 HTTP 서버 위에서 동작한다
(`web/ARCHITECTURE.md` §3, §8). IP가 바뀌거나 시연장 WiFi가 불안정하면
QR 접속이 깨질 수 있다는 게 알려진 제약이었고, 이를 Bluetooth로 우회할 수
있는지가 논점이었다.

## 결과

기각. 근거 3가지:

1. **영상 스트리밍 대역폭 부족** — 이 앱의 핵심 기능은 라이브 카메라
   (MJPEG)인데 BLE는 이를 감당할 대역폭이 안 되고, Bluetooth Classic(SPP)은
   그나마 낫지만 브라우저 API로 접근 불가 → 네이티브 앱 필요 → PWA로
   결정한 이유(`web/ARCHITECTURE.md` §2)와 정면 충돌.
2. **iOS Safari가 Web Bluetooth 미지원** — "QR 스캔 후 설치 없이 3초 접속"
   이라는 핵심 목표(`APP_PLAN.md` §1, §14)가 아이폰 사용자 전원에게서
   깨진다.
3. **원래 병목을 안 풀어준다** — PTZ 명령 같은 저대역폭 채널만 Bluetooth로
   빼도 영상은 어차피 WiFi가 필요해, 사용자가 실제로 겪는 "네트워크
   의존성" 문제 자체는 해결되지 않는다.

네트워크 의존성 문제는 기존에 논의된 mDNS(`healthbot.local`) 또는 UNO Q
자체 핫스팟(hostapd) 쪽으로 대응하는 방향을 재확인 — 둘 다 `APP_PLAN.md`
§5에 설계는 있으나 아직 코드 미구현 상태.
