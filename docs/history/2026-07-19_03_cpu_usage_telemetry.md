# 2026-07-19 — 라이브 화면 CPU 사용률 표시 + 디바이스 여유 실측

## 시점

2026-07-19. PTZ 관성 추적 작업(`v3`, [`2026-07-19_02`](2026-07-19_02_ptz_time_based_control_and_loss_recovery.md))
을 마치고 웹 UI를 손본 첫 작업.

## 사건

메인 라이브 화면 텔레메트리에 **CPU 사용률 카드**를 추가했다. 기존에 FPS /
지연 / CPU 온도 / RAM 4개가 있었으나 **사용률은 없었다** — 온도는 있는데
"얼마나 쓰고 있나"는 볼 수 없는 상태였다.

작업 중 **디바이스 CPU가 이미 83%** 라는 것이 실측으로 드러났다.

## 배경 — 왜 필요했나

디바이스가 11 FPS로 동작하는데, 이게 "인식 모델이 무거워서"인지 "다른 데서
CPU를 먹고 있어서"인지 구분할 지표가 없었다. `cpu_temp_c`는 발열만 보여주지
부하 여유를 알려주지 않는다.

## 구현

### 백엔드 — psutil 없이 `/proc/stat` 차분

기존 `get_rss_mb()` / `get_cpu_temp_c()`가 `/proc`을 직접 읽는 패턴을 그대로
따랐다. `requirements.txt`에 의존성을 추가하지 않기 위함.

```python
def get_cpu_percent():
    """시스템 전체 CPU 사용률 0~100 (전 코어 합산을 100%로 정규화)."""
```

**주의할 점 두 가지:**

1. **`/proc/stat`은 부팅 이후 누적값**이라 값 하나로는 사용률을 알 수 없다.
   직전 호출과의 차분으로 구간 사용률을 낸다 → **첫 호출은 항상 `None`**.
   프론트는 이때 `—`를 표시한다.
2. **컨테이너 안에서도 `/proc/stat`은 호스트 전체 값**을 보여준다(procfs가
   네임스페이스로 분리되지 않음). 따라서 이 값은 **디바이스 전체 부하**이지
   이 프로세스만의 사용률이 아니다. 의도한 동작이다 — "100% 기준으로 얼마나
   쓰고 있나"를 보려면 전체 부하가 맞다.

### 프론트엔드

- `Stats` 타입에 `cpu_percent: number | null` 추가
- 텔레메트리 그리드 4칸 -> 5칸, CPU 카드 신설
- **100% 기준 채움 막대**를 같이 둠 — 숫자만으로는 여유가 얼마나 남았는지
  가늠이 안 된다. 부하 구간별로 색이 바뀐다:

| 구간 | 색 (기존 디자인 토큰) |
|---|---|
| ~70% | `--success` |
| 70~90% | `--warning` |
| 90%~ | `--danger` |

- `role="meter"` + `aria-valuenow` 로 접근성 처리

## 결과 — 검증

**`vmstat`으로 교차 확인해 계산이 맞는지 검증했다.**

```
vmstat:  us=76  sy=7  id=16   ->  사용률 = 100 - 16 = 84%
stats.json:  cpu_percent = 82~83%
```

1~2%p 차이는 샘플링 시점 차이 범위. 계산식이 맞다.

`nproc` = 4 (4코어). 표시값은 전 코어 합산을 100%로 정규화한 것.

## 중요 관측 — 디바이스 여유가 17%뿐이다

**측정 시점 CPU 83%.** 추론(MoveNet Thunder INT8, 11 FPS, 4스레드)과 MJPEG
인코딩이 대부분을 쓰고 있다. **이미 warning 구간(70~90%)이다.**

앞으로 기능을 추가할 때 반드시 참고해야 할 수치다. 특히:

- FPS를 올리려는 시도는 CPU 여유가 없어 한계가 있다
- MCU 트랙(보류 중)이나 KWS 같은 추가 워크로드를 얹으면 이 17%를 나눠 써야 한다
- 발열(51도)은 아직 여유가 있으나 지속 부하 시 재확인 필요

## 알려진 제약

**이 카드는 900px 이상에서만 보인다.** 기존 텔레메트리 행
(`.hcb-live__telemetry`)이 `display: none`이고 데스크톱 미디어 쿼리에서만
그리드로 뜨는 구조라, CPU 카드도 같은 규칙을 따른다. **폰으로 `/app`을 열면
보이지 않는다.** 모바일 노출이 필요하면 별도 작업이 필요하다.
