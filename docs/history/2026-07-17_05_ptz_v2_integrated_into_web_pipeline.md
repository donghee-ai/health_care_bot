# 2026-07-17 — PTZ v2 추적 로직을 웹앱 본 파이프라인에 통합

## 시점

2026-07-17 (PTZ+스쿼트 v2
[2026-07-17_04](2026-07-17_04_ptz_squat_counting_v2.md) 이어서)

## 사건

독립 테스트 스크립트에만 있던 v2 추적 로직(무릎 중점 → 엉덩이 폴백, 중앙 4/6
섹터 밴드, 획득→잠금, 속도 감속)과 **서보 버스 직결 제어**를 본 파이프라인
(`src/ptz_controller.py`)에 이식했다. 이제 `src/main.py` 하나로 **웹앱(PWA) +
라이브 스트림 + 스쿼트/푸시업 카운팅 + PTZ 추적**이 한 프로세스에서 동시에 돈다.

작업 전 복원점: `backup/pre_web_integration/{src,scripts,docker}` (전체 복사본).

## 배경

- 기존 `ptz_controller.py`는 `/dev/ttyACM0`으로 `PAN +8` 텍스트를 MCU에 보내는
  구조였는데, UNO Q에는 MCU로 가는 raw serial 경로가 없어 **실기에서 작동 불가**
  였다(미검증 상태로 남아있던 잠재 버그). 서보 버스를 Linux가 직접 구동하는
  방식으로 교체하는 것이 통합의 핵심이었다.
- 웹앱에는 이미 스쿼트 카운팅이 있었으므로, v2가 실제로 더한 것은 **작동하는
  PTZ 추적 경로**다.

## 결과

**구조 변경**
- `scripts/st3215_bus.py` → **`src/st3215_bus.py`** 로 이동(런타임 모듈로 승격).
  벤치 스크립트 3종은 `src/`를 import 경로에 추가해 그대로 동작(회귀 확인).
- 무릎/엉덩이 중심 헬퍼(`knee_center_normalized`, `hip_center_normalized`)를
  `src/pose_utils.py` 공용 모듈로 승격 — 스크립트와 컨트롤러가 같은 코드를 씀.
- `src/ptz_controller.py` 전면 재작성: 버스 직결 + v2 추적 로직. **공개 API
  (`snapshot`/`set_auto_track`/`manual_pan`/`manual_tilt`/`manual_center`)를
  그대로 유지**해 `src/http_server.py`(웹 `/api/ptz`)는 **무변경**.
- `src/main.py`: `ptz.update(x_norm, y_norm, now_ms)` → **`ptz.update(kp, h, w, now_ms)`**
  (컨트롤러가 keypoint에서 목표점을 직접 산출). PTZ CLI 플래그를 새 파라미터로 교체.
- `docker/run.sh`·`Dockerfile`: 시리얼 디바이스를 `/dev/ttyACM0` → **`/dev/ttyUSB0`**
  (서보 버스 어댑터)로 변경.

**pitch 프레이밍 문제 발견·수정 (중요)**

두 파라미터의 의미:
- `pitch_target_y` = 무릎을 화면 **세로 어디에** 놓을지 목표 (0=맨위, 1=맨아래)
- `pitch_deadzone` = 목표에서 이만큼 벗어나기 전엔 **안 움직임** (화면 높이 대비)

| | 이전 | 변경 후 |
|---|---|---|
| `pitch_target_y` | 0.5 (화면 정중앙) | **0.62** (아래쪽 1/3 부근) |
| `pitch_deadzone` | 0.10 | **0.20** |
| 안 움직이는 세로 구간 | 40%~60% (폭 20%) | **42%~82% (폭 40%)** |

바꾼 이유 — 합성 keypoint 검증에서 실제로 재현된 두 문제:

1. **잠금이 영영 안 걸림.** 사람이 서 있으면 무릎은 자연스럽게 화면 아래쪽
   (y≈0.79)에 잡히는데, 목표가 0.5면 오차 0.29가 데드존 0.10을 항상 초과 →
   계속 "존 밖" 판정 → LOCK이 안 걸리고 카메라가 계속 아래로 틸트하려 듦.
   변경 후: 목표 0.62, 무릎 0.79 → 오차 0.17 < 데드존 0.20 → 정상 잠금.
2. **스쿼트마다 카메라가 끄덕임.** 스쿼트는 무릎이 상하로 움직이는 운동이라
   데드존이 좁으면 카메라가 매 rep을 따라 움직여 영상·카운팅 화면이 흔들림.
   데드존을 폭 40%로 넓혀 **운동 동작은 무시하고, 사람이 자리를 크게 옮겼을
   때만** 세로 프레이밍을 교정하도록 함.

재검증: 무릎 상하 진동(380↔300px) 시 **yaw/pitch 모두 전혀 안 움직이고 LOCK 유지**.

참고: 좌우(yaw)는 이 두 값과 무관 — yaw는 중앙 4/6 섹터 밴드로 따로 판정한다.
조절은 `--pitch-target-y` / `--pitch-deadzone` 플래그로 가능.

**검증**
- 합성 keypoint: 중앙 → LOCK(10프레임), 스쿼트 진동 → 무동작, 우측 밴드 밖 →
  잠금 해제 후 추적 재개, 미검출 → grace 후 LOST. 전부 정상.
- 실기 `main.py` 실행: `[ptz] 버스 연결 COM9 @ 1000000, 중앙(180/180) 정렬 후 시작`,
  이전 실행에서 틀어져 있던 서보(yaw 162.4)를 **시작 시 자동 중앙 정렬(→179.7)**.
  웹서버 `:8080` `/app`(뷰어·운영자) 기동, 카메라·추론·카운터 정상.
- 서보 미연결/전원 없음이면 **disabled 모드로 degrade**(추적 계산만, 웹 UI 정상).
  명령 카운터는 실제 전송된 것만 집계하도록 수정.
