## 4. 고친 것

**동작과 어긋났던 것**

1. `03` §7 — 쿨다운을 "250 → 80 ms로 고쳤다"고 서술했으나 **실동작은 250 ms**.
   `ptz_controller.py`의 80.0은 `main.py` CLI 기본값 250.0에 덮여 도달하지 않는 죽은
   값이다. 사용자 판단으로 **런타임(250)을 정답으로 두고 문서를 맞췄다.**
2. `06` — `pitch_sign=+1`이 정상이라고 적혀 있던 것을 `-1`로 정정.
3. `05` §9 — "작업본과 배포본이 동일 내용"이 거짓이 돼 있었다. `design_demos/
   live_apple-design.html`(32 KB, 07-26)에는 경비 UI·QR 생성기가 없어, 문서에 적힌
   복원 명령을 그대로 실행하면 8월 작업이 통째로 롤백된다. **경고로 교체하고 복원
   경로를 backup/git으로 바꿨다.**

**경비 모드 서술 추가** — `00`(출력·검증상태·트리) `01`(모듈경계·상태소유권·degrade)

## 5. 남긴 판단

- **80 ms로 내리는 것은 코드 변경이므로 하지 않았다.** 필요하면 `run.sh`에
  `--ptz-cooldown-ms 80`을 추가하면 된다(`03` §7에 방법만 적어둠).
- `docker/Dockerfile`의 `--mode auto`는 그대로 뒀다. 이미 `01`·`08`·`09`가 함정으로
  정확히 기술하고 있고 `run.sh` 경로에서는 드러나지 않는다.
- `design_demos/live_apple-design.html`은 지우지 않았다. 옛 시안으로서의 가치는 있고,
  문서에 "복원용 아님" 경고를 붙이는 쪽을 택했다.

## 5-1. 웹 계층을 "확정"으로 못박음 (같은 날 추가 결정)

사용자 판단으로 **Fluid(`web/dist/index.html`)를 확정 UI로 고정**했다. 그동안 문서가
Fluid를 "아직 결정 안 된 후보"로 다루고 있었다 — `09` §5-2에 "Fluid로 굳힐지 React 시안
6종을 정리할지 결정"이 미결 항목으로 남아 있었고, `web/src/versions/registry.ts` 주석도
"확정된 UI가 아니라 검토 중인 후보"라고 적고 있었다. 실기에서 이미 이것만 쓰고 있는데
문서만 유보 상태였던 것.

- `05` 맨 앞에 "Fluid가 확정 UI다(2026-09-08). 후보가 아니라 고정" 명시.
- `web/src/` React 계층은 **보관 계층**으로 격하. `web/DESIGN.md`·`APP_GUIDE.md`도
  "갱신하지 않는 보관물"로 표기(`00` §6-3).
- `09` §5-2의 미결 항목을 "확정됨, 남은 건 결정이 아니라 정리"로 교체.
- `05`의 React 시안 이름을 `registry.ts` 실제 id로 정정 — 문서의 CARE·LIVE는 없고
  실제로는 `rehab`·`session`이다.

### 곁가지로 발견한 것 — `scripts/mock_serve.py`가 깨져 있다

프론트 목업 개발 경로를 문서에 다시 쓰려다 발견했다. 2026-07-26에 삭제된
`PushupCounter`를 import해서 **실행 즉시 `ImportError`가 난다.** `07` §7과 `08` 증상
색인, `09` §5-3 부채 표에 기록만 하고 코드는 고치지 않았다(문서 작업 범위 밖).

참고로 `mock_serve.py`는 `/app`도 서빙하므로, 고치기만 하면 **React·npm 없이
`http://localhost:8090/app`에서 Fluid를 그대로 띄울 수 있다.** `07` §7을 그 흐름 중심으로
다시 썼다.

## 6. 재발 방지

- **문서의 기본값을 코드의 데이터클래스에서만 읽지 말 것.** CLI 인자가 생성자에
  주입되면 그쪽이 이긴다. 실동작값은 `docker inspect`의 실행 인자로 확인한다.
- **"두 파일을 같이 맞춰둔다"는 관례는 검증 없이 문서에 남기면 거짓이 된다.**
  단일 소스를 정하는 편이 낫다 — 이번에 `web/dist/index.html`로 일원화했다.
- 기능을 추가하면 README만 고치고 끝내지 말 것. 상설 문서에 담당 절이 반드시 있다.
- **"검토 중인 후보"라고 써둔 것은 결론이 나면 반드시 회수할 것.** 실기에서는 이미
  Fluid만 쓰고 있는데 문서와 코드 주석이 몇 달째 "후보"라고 말하고 있었다. 유보 표현은
  읽는 사람을 잘못된 선택지 앞에 세운다.
- **문서에 적은 개발 명령은 실제로 한 번 실행해볼 것.** `mock_serve.py`는 종목 개편
  때부터 깨져 있었는데 문서에는 정상 절차로 남아 있었다.
